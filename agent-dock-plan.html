01 / Vision

The approval inbox for coding agents

01 · BE NOTIFIED

Notice the wait

Show a discreet top-of-screen panel when an agent blocks for approval, regardless of which desktop Space or application is active.

02 · UNDERSTAND

See enough context

Agent, project, session, operation, command or file target, requested privilege and optional diff/details—all without returning to Terminal.

03 · DECIDE

Respond immediately

Allow once, deny, or save a precise persistent rule when the underlying agent API actually supports it. Optionally send rejection feedback.

Product boundary: Agent Dock routes explicit human decisions. It does not silently elevate permissions, circumvent sandbox policy, or override higher-priority managed restrictions. Native terminal prompts remain the fallback if Agent Dock is unavailable.

Design principles

Low interruption: small by default; expands only when attention is needed. Low ambiguity: every decision identifies a specific tool call and scope. Low surprise: never disguise allow-always as allow-once. Fast recovery: one click opens the originating terminal when context is insufficient.

02 / Interactive product mockup

Permission requests that never interrupt your work

Agent Dock slides down beneath the macOS menu bar (or near the notch) in a non-modal, non-activating panel. It must never capture keyboard focus merely by appearing, change Spaces, prevent clicks elsewhere, or blanket the screen with an invisible click-catching overlay. Hovering the compact prompt expands it. The menu-bar icon is the durable inbox.

Behavioral contract: After a new request, show the expanded panel for 10 seconds; if untouched, collapse to one line. At 30 seconds from arrival, hide the passive panel entirely. Hover on the compact panel temporarily expands it, and mouse-out starts a 1-second re-collapse delay. Dismissing hides a card; it does not deny or answer it.

New request: expanded, timer running. Click the simulated menu-bar icon to reopen at any time.

Expanded alert

Shows session title, provider, workspace, requested command/diff, and Allow once / Deny / Dismiss controls. Optional scope-specific persistent permissions appear only where the native agent supports them.

Compact single-line alert

Shows a count plus the latest session (“Implement macro tracker · needs approval”), with a small × button to dismiss. The whole chip is hoverable and clickable for details, while the rest of the desktop remains interactive.

Hidden, not resolved

At 30 seconds, the floating prompt disappears. The menu-bar badge still shows the number of outstanding actionable requests. Dismissed items remain in the inbox and can be reviewed later.

Session identity

Use custom/auto-generated session title when available; project and concise request detail when not. Titles refresh after rename; never use session title to route approvals.

03 / Notification presentation states

Two orthogonal state machines: request vs visibility

Never couple UI dismissal or an auto-hide timeout to an agent permission decision. A permission can be pending while its floating surface is visible, compact, or entirely hidden. The badge represents pending requests, not visible notifications.

RESOLVEDallow / deny returned

Other outcomes: expired, cancelled, fallback. Dismiss and collapse are not permission outcomes; only explicit native actions or agent-side completion settle a request.

→

→

Manual dismiss jumps to HIDDEN immediately. Hover in COMPACT opens EXPANDED temporarily; mouse-leave returns to COMPACT after 1 second. Menu-bar click opens PINNED_INBOX.

Clock rule: use monotonic timestamps and one cancellable timer controller per floating presentation. Expiry/deadline of the underlying permission is independent of 10s/30s visibility rules. If an agent times out before the user returns to the badge, the request is removed as stale, never left as an actionable zombie.

Multi-request behavior and status item

  • Menu-bar NSStatusItem displays an Agent Dock icon and numeric badge for outstanding actionable requests. Badge is hidden/zero when none; cap visual display at 99+, retain actual count in accessibility label.
  • In expanded transient view, display the latest arrival with a “2 more waiting” queue affordance. Hovering a particular compact card keeps that card selected; no automatic switching while pointer is inside.
  • Menu-bar click is a user-initiated, persistent open state, unlike hover expansion. Panel supports scrolling through all requests, explicit Dismiss on each card, and optional “Hide panel” close.
  • Dismissed cards remain in the menu-bar list until resolved/expired. Distinguish “dismiss” (hide surface) from “deny” (answer no); never use the word “clear” ambiguously.
  • Badge changes occur only on request arrivals and broker terminal outcomes; menu-bar clicks, hover and dismissal do not change badge number.
  • In quiet/DND/full-screen situations, use OS-consistent behavior: menu bar always available when OS exposes it, but do not promise unconditionally visible overlays above exclusive full-screen contexts. Verify with real macOS testing.
  • Optional future preference: per-app suppression, reminder pulse, compact timeout, auto-hide timeout, badge-only mode. Default timings are fixed to 10s, 30s, 1s initially.

Accessibility, focus and input

Non-activating show must preserve the currently key window and input focus. Mouse actions on the panel work without requiring a Space change; keyboard/VoiceOver should be available when the user intentionally opens the menu-bar inbox or requests focus. Avoid global mouse event interception or any full-screen transparent overlay. Use native NSStatusItem, NSPanel, NSWindow activation choices and window collection behavior verified on actual Macs.

03 / Interaction flows

Key user journeys

A. Permission arrives while working elsewhere

  1. Claude requests a Bash command. The synchronous hook receives an event.
  2. Hook publishes a request to the local Agent Dock broker and waits for a correlated response.
  3. Panel expands on current display/Space; presents command, project and source session.
  4. User selects Allow once; broker responds to the hook; hook prints documented JSON to Claude.
  5. Prompt disappears; another pending request, if any, becomes active.

B. Save a project-scoped exception

  1. Claude asks for an operation for which native permission suggestions are available.
  2. User opens “Approval options” and sees an explicit rule and scope preview.
  3. User confirms a project-local persistent rule, not an unbounded global exemption.
  4. Hook returns updatedPermissions with the exact supported permission update.
  5. Claude validates/applies the rule; Agent Dock records outcome as requested, not guaranteed, until verified.

C. Several agents request at once

  1. Broker receives three requests from distinct processes/sessions.
  2. Collapsed badge reads “3 waiting”; expanded queue sorts oldest first by default.
  3. Each item has a stable request ID and identity. User selects one and decides.
  4. Only the matching hook waiter receives the decision; unrelated agents remain paused.

D. Panel unavailable or request becomes stale

  1. Hook cannot reach broker or broker detects no usable GUI.
  2. Hook returns no decision quickly; agent’s native prompt takes over when supported.
  3. Any timeout, native approval or ended process marks the card stale; stale cards cannot be approved.
  4. Reopening the panel shows a clear diagnostic, not a fabricated success state.

Nonfunctional targets

Responsiveness

Target dock presentation within 300 ms of broker receipt on a warmed process; target low idle CPU and memory. Benchmark actual Mac hardware.

Privacy

All data local. No analytics or external requests. Sensitive commands never logged by default; optional history uses redaction and retention limits.

Accessibility

VoiceOver labels, proper keyboard focus, reduced motion, contrast, UI scale and clear touch targets.

05 / Scope discipline

What to ship, and what to defer

MVP First useful release

  • Menu-bar app and top drop-down in active Space.
  • Claude Code + Codex allow/deny via official synchronous hooks.
  • Multiple pending request queue, detail view, source identification.
  • Launch-at-login installer/uninstaller; hook install with backups.
  • Clear fallback when host is disconnected.
  • Simulated request generator for development on any OS.

Later After validating core flow

  • Claude persistent rule controls and question/plan forms.
  • Reliable per-terminal-window focus integration.
  • Expanded diff preview / structured risk hints.
  • Codex persistent approvals through separately validated native APIs.
  • Agent status/timeline, usage analytics, additional agent adapters.
  • Signed/notarized distribution, polished autoupdate system.

Success metric: median time from permission request to human answer; number of forced Space or terminal switches per decision; false/duplicate/missed prompt count; never an unintended allow. Product goal is to eliminate workspace navigation for the common case, not replace terminal operation or build a complete agent IDE.

06 / External research · verified against current references

Integration facts that shape the design

Claude Code

Official PermissionRequest hook executes on a permission decision path and can return hookSpecificOutput.decision.behavior with allow or deny. It can also emit updatedInput and updatedPermissions with distinct session, project-local, project and user destinations. The suggestions array is not guaranteed to match all options visible in native dialogs. The agent may use a native prompt or another host callback, so race/fallback cases must be tested. Official hooks reference.

Codex

Official PermissionRequest synchronous hook also supports allow and deny. Its published contract explicitly says updatedInput, updatedPermissions and interrupt are not currently supported for this hook. Local user hook file is ~/.codex/hooks.json (or $CODEX_HOME/hooks.json); trust review may be needed through /hooks. Official Codex hooks.

Codex app-server

App-server exposes client-owned approval JSON-RPC requests including item/commandExecution/requestApproval; however, these belong to sessions controlled by that app-server client. Do not assume Agent Dock can attach to and answer an unrelated running terminal or desktop client over app-server. The synchronous hook is the MVP integration. Official app-server.

Existing UX precedent

AgentPeek demonstrates an agent-permission panel in the Mac notch, with multiple queued prompts, keyboard shortcuts, and direct answers for supported agents. Agent Dock should reproduce the general interaction model, not copy proprietary assets or code. An open-source implementation also demonstrates a window-plus-hook approach. AgentPeek permission UI · coding-agent-popup.

Compatibility risk: Hook events, supported tool names, front-end client behavior and permissions can change between agent versions. Treat docs as the current baseline, but require an automated and manual compatibility matrix before claiming full macOS/Claude Desktop/Codex Desktop coverage. In particular, Claude sandboxed network permission events may require a separate Notification observation/fallback path rather than the ordinary PermissionRequest hook.
07 / System blueprint

One local broker, two hook adapters, one native UI

Use a single user-session Agent Dock process for the interface and request broker. Agent-side hook commands are short-lived, blocking clients. The broker owns the queue, authorization decisions, expiration, and UI notifications. Avoid running a separate privileged daemon or opening a network listener.

Recommended module boundaries

agent_dock.core

Typed domain models, permission enums, scope rules, request state machine, expiration, request matching, safe labels, persistence.

agent_dock.broker

Asyncio Unix-domain socket server, authenticated peer checks, request/response correlation, bounded queue and UI observer notifications.

agent_dock.ui

PyObjC AppKit status item, NSPanel/window controller, presentation geometry, keyboard handling, accessibility and macOS main-thread bridge.

agent_dock.adapters

Separate Claude/Codex hook parsing and response formatting. Version-gated capabilities. No UI logic in hook scripts.

agent_dock.install

Idempotent config patching; backups; preserved existing hooks; LaunchAgent plist; uv-managed application environment; uninstall and restore.

agent_dock.testing

Fixtures for supported hook shapes, fake hook waiter, concurrency/timeout test harness, mocked UI and macOS smoke tests.

08 / IPC & lifecycle

Make permission decisions atomic and correlated

Orthogonal presentation state: expanded → compact → hidden is not part of this permission lifecycle. See notification states. Never allow/deny on passive timeouts or dismissal.

Request lifecycle

RECEIVEDvalidated from hook
→
PENDINGqueued and displayed
→
CLAIMEDsingle user action
→
RESOLVEDresponse delivered

Alternative terminal states: EXPIRED (timeout or shutdown), CANCELLED (hook/client disconnected), FALLBACK (no usable broker). Only PENDING requests can be claimed. A claim is an in-memory atomic transition keyed by a random request ID; replayed decision packets are rejected.

Example broker envelope (internal schema, not agent-native JSON)

{
  "protocol_version": 1,
  "request_id": "d3d9a8f1-...",
  "agent": "claude",
  "session_id": "agent-native-session-id",
  "display_title": "Implement macro tracker",
  "title_source": "index",
  "hook_pid": 24680,
  "timestamp": "2026-11-23T10:00:00-08:00",
  "cwd": "/Users/example/projects/frontend",
  "type": "permission",
  "tool_name": "Bash",
  "tool_input": {"command": "npm run build"},
  "native_permission_suggestions": [],
  "supported_actions": ["allow_once", "deny", "fallback"],
  "deadline_ms": 45000
}

Response: broker sends {"request_id":"...","decision":"allow_once"} to the originating hook waiter, not directly to Claude/Codex. Adapter serializes the agent-specific JSON. “Always allow” requires a confirmed native scope payload; the broker must never mint a broad permission rule from string matching.

Exact flow and failure points

IPC contract

  • Use a per-user Unix-domain socket under a private 0700 runtime directory with socket mode 0600; verify peer UID where the OS permits and test against same-user forgery. This limits cross-user access; same-UID malware is not preventable by ordinary file permissions.
  • Length-prefixed UTF-8 JSON; explicit protocol version; max request size (e.g. 256 KiB); bounded queue (e.g. 100); reject malformed payloads.
  • One persistent connection per waiting hook, so a disconnect automatically invalidates its card. A hook times out locally even if the broker does not.
  • Request timeout is configurable and must stay beneath agent-side hook timeout. Start with 45 seconds as a product default to test, not a guaranteed timeout for every agent configuration.
  • Broker has one authority for request state. GUI dispatches decisions by ID and must show a settled state only after broker acknowledgement; never interpret a button press as evidence that Claude/Codex executed the action.
09 / Concrete agent adapters

Two agents, not one universal permission format

Claude Code installation

Installer adds one managed command hook entry to the existing ~/.claude/settings.json, preserving other hooks and settings. Use the absolute Python interpreter installed for Agent Dock, not a shell activation or a dynamic uv run in the hot path. Install optional session/activity and notification hooks in a later phase.

{
  "hooks": {
    "PermissionRequest": [{
      "matcher": "*",
      "hooks": [{
        "type": "command",
        "command": "/ABS/PATH/TO/AGENT_DOCK_PYTHON -m agent_dock.hook claude",
        "timeout": 60
      }]
    }]
  }
}

Illustrative fragment, not a replacement settings file. Confirm wildcard matching and current timeout semantics against installed Claude version. The agent controls whether this hook fires; already-permitted actions never require a dock decision.

Claude hook decision response

{
  "hookSpecificOutput": {
    "hookEventName": "PermissionRequest",
    "decision": { "behavior": "allow" }
  }
}

For deny, use behavior: "deny" and optional message. For persistent permission, only forward a validated updatedPermissions payload using suggestions native to this request. For AskUserQuestion or ExitPlanMode, a complete updatedInput may be needed; build a dedicated adapter, not a generic “allow” button. The hook might race with another host approval callback; stale cards must be removed.

Codex installation

Installer merges a synchronous PermissionRequest command into ~/.codex/hooks.json (or $CODEX_HOME/hooks.json), preserving existing configuration. Codex may require explicit trust of the hook definition in /hooks; setup must guide the user through that step instead of attempting to bypass it.

{
  "hooks": {
    "PermissionRequest": [{
      "matcher": "*",
      "hooks": [{
        "type": "command",
        "command": "/ABS/PATH/TO/AGENT_DOCK_PYTHON -m agent_dock.hook codex",
        "timeout": 60
      }]
    }]
  }
}

Codex decision output shares the documented hookSpecificOutput shape for allow/deny. Do not return updatedPermissions to Codex: current docs explicitly reject it. UI should say “Allow once” and “Deny”; a native “Always allow” is not exposed unless an independently verified integration is implemented.

Sandbox caveat: If a coding agent is running inside Docker/Linux while Agent Dock runs on the Mac host, the hook process is inside the container. A macOS-local socket is not automatically visible there. Treat container access as a separate planned feature requiring an explicitly mounted socket or an authenticated relay. Do not silently expose a TCP port.

Requirements and edge cases

  • Use compound key (provider, session_id) throughout; title is mutable, non-unique presentation metadata. Include a separate immutable request_id for the permission itself.
  • Resolver should be non-blocking and bounded (asyncio.to_thread/worker executor); initial request can render fallback immediately, then title can update asynchronously.
  • Watch session metadata files for rename changes via FSEvents or safe polling, with debounce; re-check while a request is visible. Avoid scanning all transcripts on every UI frame.
  • Choose title precedence: verified explicit session title → provider generated title → broker-side cached last title → project basename + action summary → session-ID suffix. Record a title_source for diagnostics.
  • Resolve paths carefully (home expansion, sandbox host mapping, symlinks), and do not mistake two sessions in the same project for one session.
  • Security: reject huge/corrupt index files, follow no unexpected symlinks outside approved agent state folders, never send transcript contents over network, never log raw prompts by default.
  • Tests: renamed Claude and Codex sessions while approval pending; initial generated titles; absent/inaccessible metadata; two sessions same title; cold start; rapid edits/partial writes; future version format changes.

10 / Platform & packaging

Python core, native macOS shell

Preferred stack

Python 3.12+ managed with uv for broker, adapters, settings and test code. PyObjC / AppKit for a true macOS NSStatusItem, NSPanel or borderless window, display geometry, event dispatch and optional hotkeys. asyncio for IPC. Use a native NSView UI or local bundled HTML/CSS in a WKWebView if richer design iteration is preferred. Never load the panel from a remote server.

App lifecycle

Package as a user-level background menu-bar app (LSUIElement in bundled Info.plist), not a root service. A user launchd LaunchAgent starts it at login and restarts on demand according to configured policy. launchctl bootstrap gui/$UID … and bootout need smoke-testing on target macOS. An app bundle and signing/notarization become release requirements.

Window priority: passive NSPanel presentation must be non-activating and non-modal; reserve a user-initiated, focusable inbox state for keyboard and assistive technology. Do not use runModal, NSAlert, or an always-on-top full-screen interception layer.

Space and display behavior

  • Use AppKit collection behavior flags such as canJoinAllSpaces / fullScreenAuxiliary where suitable, and test actual behavior. Don't assume a panel visible in ordinary Spaces will automatically overlay every full-screen or Stage Manager context.
  • Choose anchor point using safe-area/menu-bar geometry. Not every Mac has a notch; standard menu-bar dropdown is the reliable baseline. Account for notch/dynamic-island geometry, multiple displays, menu-bar position, scaling and screen changes.
  • Keep an idle nonactivating representation. Make the decision surface focusable for keyboard/VoiceOver; record and restore previous app focus carefully, without synthesizing untrusted keyboard events into other apps.
  • AppKit GUI updates must run on main thread. Broker I/O may use a worker asyncio event loop; use explicit, thread-safe dispatch and shutdown handling.

11 / Security, privacy, resilience

Approvals are security-sensitive actions

Least privilege by construction

Never run as root. No Accessibility or Screen Recording permission by default unless a concrete feature requires it. Do not inspect terminal windows or simulate keystrokes to accept prompts. Don’t auto-approve commands based on project label, process name or string pattern.

Rule safety

Allow-once is always the default focused action. Show exact rule text, destination and consequence before saving a persistent rule. Prefer narrow project-local rules. Never make broad tool-wide rules from guessed user intent; respect managed policy denial and missing suggested options.

Prevent stale or wrong approvals

Request IDs are unique per hook invocation. Reject late responses, duplicate clicks, dead processes, disconnected clients and events from previous broker instances. Broker must not reassign an old response to a new pending request.

Settings integrity

Installer acquires a lock, makes a timestamped backup, parses and minimally merges JSON, writes atomically, and has a conservative uninstall that deletes only its own entries. Warn rather than overwrite malformed settings.

Privacy of displayed commands

Commands, environment and tool inputs might contain credentials, internal paths or confidential data. Do not persist raw payloads by default. Offer privacy blur/sensitive-screen mode, truncate in collapsed status, and remove expired payloads from memory.

Failure-safe operation

Broker absence and malformed responses lead to native fallback, not allow. Hook cancellation and timeout are bounded. App restart does not resurrect a request unless the original hook is still connected and the protocol reestablishes identity safely.

Threat-model assumption: Agent Dock is trusted software operating under the current macOS user account. An attacker who already controls that account can generally tamper with user-owned hooks or IPC; user-only file permissions protect other users and accidental exposure, not fully compromised same-user processes.
12 / Implementation roadmap

Build in vertical slices

PHASE 0 · COMPATIBILITY SPIKE

Prove the interception contract

Build tiny Claude/Codex hooks that accept JSON on stdin, block on a fake local socket, and emit allow/deny. Check actual CLI and desktop builds on macOS; capture sanitized request fixtures. Verify fallback, timeout and hook-trust interactions. Exit: end-to-end manual decisions work for one request each.

PHASE 1 · CORE MVP

Broker + queue + one native window

State machine, IPC, request validation, correct correlation, NSStatusItem/NSPanel, allow/deny UI, basic identity. Stubbed requests allow UI work without launching agents. Exit: 10 concurrent fake agents route correctly.

PHASE 2 · INSTALLABLE TOOL

Login startup and real agent config

uv-based package, app bundle/launcher, LaunchAgent, safe hook merge, uninstall, status/diagnostics, error messages. Exit: fresh Mac install, login and recovery tested without manual config edits.

PHASE 3 · POWER USER POLISH

Scopes, keyboard, multi-display

13 / Definition of done

Acceptance scenarios for the coding agent

  1. Working elsewhere: start Claude Code in one Terminal Space, move to a browser in another, trigger permission and approve from the dock without changing Spaces.
  2. Multiple terminals: start two Claude and one Codex session; all pending requests show correct project/session labels and answers go to the right process.
  3. Codex contract: Codex allows/denies correctly, and never displays a non-working persistence option.
  4. Claude scoped rule: user can inspect and confirm a real, supported project-scoped suggestion; exact change is applied and separately verified. No suggestion means no promise of persistence.
  5. Recovery: quit Agent Dock, trigger an approval, and observe the agent's native approval flow rather than a silent allow or indefinite freeze.
  6. Startup: reboot or log out/in; menu-bar app starts and hooks continue to work. Uninstall reverses startup and own hook entries without damaging other config.
  7. Safety: stale and duplicate decisions never affect a second call; session data is neither uploaded nor retained indefinitely.
  8. Accessibility: all buttons can be reached and labeled using keyboard and VoiceOver; global shortcuts never cause an accidental decision without a visible focused prompt.
  9. Non-blocking arrival: typing in another app continues uninterrupted while expanded notification slides into view; clicking elsewhere continues to work normally.
  10. Timers: new prompt expanded initially, one-line after 10s, hidden after 30s total; hover re-expands and leaves compact after 1s; no timer ever triggers allow/deny.
  11. Dismissal and recovery: × in both expanded and compact hides notification without resolving it; menu-bar badge retains count; click reopens the exact pending request.
  12. Menu-bar inbox: two simultaneous permissions show badge 2; dismissing one leaves badge 2; allowing one decrements to 1 after broker acknowledgement; all resolved gives no badge.
  13. Session identity: a named Claude and renamed Codex request show their latest titles; changes propagate live, duplicate titles never affect routing; missing metadata uses a safe fallback.
  14. Hover concurrency: while reviewing a command, a second request arriving does not replace the content under the pointer and timers do not collapse an actively operated control.
Agent handoff instruction: Start by executing Phase 0 and updating the compatibility matrix based on the versions actually installed. Build the smallest end-to-end path before polishing the window. Any contract assumption that fails should be documented and resolved with an adapter change, not by injecting keystrokes into Terminal or silently weakening approval behavior.
